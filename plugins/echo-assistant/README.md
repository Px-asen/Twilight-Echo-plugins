# 回声助手 0.2.0

在 Twilight Echo 的右侧面板里检查曲库、整理音乐，再按需接入 AI 继续分析。

## 从一次曲库检查开始

1. 在插件管理中安装 `com.twilightecho.assistant.echo-0.2.0.tep`，启用后点击标题栏的「回声助手」。
2. 选择「曲库体检」或「查找重复」。这两项在本地分页检查完整曲库，无需 API，也不消耗模型 token。
3. 在对话里查看报告。体检展示格式、采样率、位深和信息完整度；重复检查展示疑似重复组及版本差异，不自动删除文件，候选顺序不代表保留建议。
4. 想进一步整理时，点击报告里的「继续分析」，编辑问题后发送。尚未配置 AI 时会打开接入设置，报告和草稿继续保留。

**检查入口、报告和 AI 分析都在这个插件的助手面板内。主程序体检页不增加 AI 按钮或插件依赖。** 已有对话可从输入区的「音乐任务」发起检查。

报告记录实际扫描数量与全库数量；完整、停止后的部分结果、曲库变化后的过期结果分别标注。重复结果最多展示 40 组，每组最多 20 首，同时保留实际总数。报告随会话保存。

## 接入 AI，再策展或调整设置

点击顶部「助手设置」→「AI 服务」，填写地址、密钥和模型；「获取模型」可读取服务返回的模型列表，也支持手动输入。可保存多套配置，在顶部切换。

| 协议 | 地址示例 |
| --- | --- |
| OpenAI 兼容 / Chat Completions | `https://api.openai.com/v1`；本地 Ollama、LM Studio 可填写自己的 `/v1` 地址 |
| OpenAI Responses | `https://api.openai.com/v1` |
| Anthropic Claude | `https://api.anthropic.com` |

本地回环服务可不填 Key。纯文本模型请关闭视觉能力。密钥通过插件私有设置存储，表单编辑已有配置时留空保留原密钥；配置列表只返回掩码。模型请求在插件进程中执行，继承应用代理设置。

- **主题歌单**：填写场景、偏好风格和首数（默认 20）。点击「填入对话」后仍可编辑，发送后从真实曲库挑选，创建前展示确认卡。
- **设置建议**：先生成可编辑的问题，让助手读取当前设置再提出建议。
- **自然语言播放**：例如“音量调到 30%”“切换随机模式”。播放控制沿用原有工具。
- **用量**：设置页显示本月调用次数和 token；金额按你填写的每百万 token 单价估算。

## 角色与快捷指令

顶部角色选择器提供「通用助手、曲库管家、歌单策展、聆听顾问」。旁边的编辑按钮可修改正文、保存预设、另存自定义角色、删除自定义角色或恢复内置内容。选择「应用到本会话」后，从下一轮开始使用新正文；正在运行的请求不变。

预设库全局保存，每个会话保留自己的角色快照。「新对话默认角色」只影响之后创建的会话。旧会话缺少角色字段时按通用助手读取。编辑器只控制角色正文；工具协议和写入确认由程序维护。

输入区「快捷指令」只把提示词填进草稿，不自动发送或播放。设置页可新增、编辑、删除并恢复默认指令；编辑后点击「保存快捷指令」。

## 输入、停止和外观

- `Ctrl / ⌘ + Enter` 发送，中文输入法合成期间不触发发送。生成中可继续写下一条草稿。
- 点击输入框右侧的停止按钮，可停止网络读取、后续工具执行、本地扫描或待确认卡。已生成文字和已完成／已提交的修改保留，未开始的操作不再启动。
- 关闭面板不等于停止。再次打开或切换会话，会恢复运行状态、已生成片段和待确认卡。
- 阅读历史时不会被增量输出拉回底部；点击「回到最新」继续跟随。
- 面板宽 420px，窄窗口自适应。底色使用中性色，强调色读取宿主的浅色／深色主题色设置（支持预置名称与自定义色），不固定紫色或绿色。深浅模式跟随宿主外观设置，系统模式跟随系统偏好；切换时不重建输入框。
- 消息和弹层使用约 180–220ms 的轻量入场效果，流式文字不重复入场；遵循系统及宿主的减少动态效果设置。

三种协议都在收到各自结束事件后结束读取，不等待连接关闭。连续 120 秒没有有效模型响应时显示错误和重试入口；等待用户确认期间不计这项超时。

## 写入确认与兼容性

修改设置、元数据、创建或追加歌单前都需要确认。元数据写入携带曲目版本号，沿用宿主乐观锁。截图与封面只在插件进程和模型之间传递，不进入聊天前端；持久化历史时省略图片数据。

- 插件 ID：`com.twilightecho.assistant.echo`
- 类型：`ui` + `tool`；API v4 / bridge v2。
- 宿主：Twilight Echo ≥ 1.3.1，且构建包含 v4 的曲库、设置、截图及 experience 中继接口。
- 权限沿用 0.1.0：`network`、`ui:inject`、`settings`、`app:settings`、`library:read`、`library:write`、`player:observe`、`player:control`。
- API 配置、会话继续使用原存储；提示词库独立保存在 `assistant.prompts`，无需破坏性迁移。

## 开发与验证

前端仍为 Vite + 原生 TypeScript，构建输出到 `ui-dist/`。在插件仓库根目录执行：

```powershell
npm run test:echo-assistant
npm run build:echo-assistant
npm run pack:echo-assistant
```

打包命令只生成 `packages/` 中的 `.tep`，不刷新市场索引、不安装或发布，也不覆盖旧版 0.1.0 包。

浏览器交互验收需要已有 Playwright 和 Chrome；通过 `PLAYWRIGHT_MODULE` 指定 Playwright 模块路径后运行：

```powershell
npm run test:echo-assistant:ui
```

它使用 production UI、真实 gateway、本地 SSE 模型和独立测试曲库，覆盖草稿、滚动、停止、确认、工作流、角色、快捷指令、主题切换、窄屏及减少动态效果。截图和结果保存在仓库 `.cache/echo-assistant-ui-*/`。

0.2.0 的测试结果和 Electron 宿主验收限制见 [验证记录](test/VERIFICATION.md)。

完整宿主安装验收：`npm run test:echo-assistant:electron`。通过 `TWILIGHT_ECHO_ROOT` 可指定带已有 `out/` 构建及 Electron 依赖的宿主仓库。该测试仅安装到独立 `.cache/echo-assistant-smoke-*/` 资料目录，不使用真实曲库、不调用付费模型。Windows 自动化启动参数中的 `--no-sandbox` 只用于隔离测试进程，不写入插件或宿主产品配置。

新增请求：`workflow.start`、`prompts.save`、`session.prompt.set`；`state` / `session.load` 返回运行快照及提示词／报告元数据，`chat.cancel` 同时支持聊天和本地扫描，原有调用方式保留。
