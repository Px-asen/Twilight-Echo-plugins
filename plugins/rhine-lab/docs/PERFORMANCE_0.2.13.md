# 0.2.13：以下载原包恢复画质

用户反馈 0.2.11 相比下载的旧包明显变糊。本轮找到并解包 Downloads 中的 0.2.9 / 0.2.10，以更早的 0.2.9 实际运行对照，保留下载文件与现有用户资料。

## 修正

- “原始”预设恢复 0.2.9 的 100% 渲染比例、1.5× 像素密度上限、原有关闭后处理 AA 的选择。0.2.10 把上限降至 1×，在设备缩放 1.5× 时损失约 56% 的内部像素。
- 原始 / 高 / 极高预设使用完整的 1000 三角形盒体；0.2.11 的自动分级把普通浏览中的 611 个架上盒体全部换成了 488 三角形代理。自动分级继续作为性能预设及手动选项。
- FXAA 保留为手动轻量选项，界面说明其柔化细线与纹理的取舍。SMAA 保留。
- 首次升级仅识别并恢复 0.2.10–0.2.12 完整匹配的低清默认配置（包括没有 modelDetail 字段的旧设置），保留帧率。迁移版本标记保证用户以后主动选择 1× / 自动分级 / FXAA 可以正常保存；自定义阴影、AO、清晰度、SMAA 或显式完整模型设置不覆盖。
- 修复开发版单通道 AO 适配与原版玻璃接触阴影着色器的组合错误。之前适配提前替换输出语句，导致原有 22% 接触阴影混合没有生效；现在只展开单通道输入，保留原输出扩展点。

帧率上限、实例矩阵复用、阴影和 AO 缓存、玻璃深度预处理、按需图集与单通道 AO 存储继续保留。恢复画质增加的成本需要重新测量，不能沿用 0.2.12 在 1× / 自动分级 / FXAA 下的占用数字。

## 验证

同一 Edge / ANGLE D3D11、1440×900 CSS 视口、1.5× 设备缩放、同一演示曲库与相机，对比下载的 0.2.9、已安装版本对应的 0.2.11 包与修正版构建。分别检查日间 / 夜间的音乐架与抽出近看。0.2.9 和修正版内部画面均为 2160×1350，0.2.11 为 1440×900；相机、模型位置和视野逐项匹配。证据位于本地 `.cache/visual-reference/`。

新增原始 SSAOPass 对照：使用同一采样核、噪声、当前相机及原版接触阴影混合，与缓存 / 单通道实现进行 GPU 像素对比；同时继续检查深度预处理和存储格式。这样不会再仅对比两条共享同一错误的优化路径。

日间 / 夜间原始 AO 对照、RGBA / 单通道存储对照、深度预处理开关对照（浏览 / 总览 / 近看 / 真实阵列）均通过，最终 GPU 读回最大差异为 0。20 项测试、32 项展示检查、画质兼容与封面内存检查通过。

独立页面与下载原包的截图并非逐像素相同：随机 AO 采样与内置封面的预处理仍有小差异。四组场景的固定画面区域 RGB 平均绝对差从 0.56–3.57/255 降至 0.20–0.96/255；大于 8/255 的通道占比从 0.94–10.22% 降至 0.00009–0.192%。这些数字用于定位偏差，不能替代原尺寸视觉检查。

原生 Electron 隔离窗口通过 1000 专辑 / 12 流派、三档 AA 切换、自动 / 完整模型切换和旧配置迁移验证。迁移在操作画质菜单之前确认所有架上盒体均使用完整模型。1920×1080 窗口、1.5× 密度时，实际内部尺寸为 2880×1620；连续切换专辑的日间 / 夜间实际提交约 57.6 / 58.1 FPS（上限 60），GPU 进程 3D 中位数约 22 / 22.5%，专用显存约 1161 / 1200 MiB。这是恢复画质后的短时样本，25% 高占用问题尚不能视为完全解决。0.2.12 的约 12% 结果使用 1× / 简化模型 / FXAA，不具备等画质可比性。

当前完整模型、1920×1080、同一质量下的 GPU 通道测试中，连续动效的总 GPU 时间由关闭深度预处理的约 2.48 / 2.47 ms 降至开启后的约 1.82 / 1.78 ms（日 / 夜）；画面读回相同。该对照仅证明深度预处理本身的收益，不能直接换算成任务管理器占用降幅。
