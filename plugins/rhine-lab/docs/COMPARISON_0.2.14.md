# 0.2.14：原版面板审计与低需求性能版标注

基准是用户 Downloads 中未修改的 `com.twilightecho.experience.rhine-lab-0.2.9.tep`，SHA-256 为 `6c3d06f65a278551b529d1e856968e27da0bc8fe53537a639d01b4f9c4869470`。保留下载原包与用户曲库。测试通过静态服务器加载原包与新版实际构建文件，只注入场景引用以读取数据和统一采样，不替换原包的渲染代码。

## 面板与画质

- 主界面、音乐库搜索、音乐库设置、专辑详情、总览、歌词、播放区的原有布局与入口保留；设置中增加帧率、模型细节、FXAA 选项及预设说明。现有设置控件没有删除。
- 三个 CSS 构建文件与 0.2.9 逐字节相同。工作台源码及独立构建模块保留原实现。网络查询、扫描和外部设备能力不因本次渲染优化改变；本次不会把控件存在当作外部服务成功的证明。
- 默认档标为“原画质优化版”：完整 1000 三角形盒体、100% 渲染比例、1.5× 像素密度上限、2048 阴影、32 采样 AO、原有景深、透明折射与纹理过滤。主场景 AA 维持原版关闭后处理的选择；SMAA 和 FXAA 可手动选择。
- 审计发现 360° 查看器的直接渲染路径曾随主画布一起关闭 MSAA，本次恢复查看器原版的 `antialias: true`。音乐面板的 360° 按钮在 0.2.9 已暂时停用，保持原有状态，不将其算作本次通过的可交互入口。
- 与下载原包的画面并非逐像素完全一致：内置纹理经过无损 WebP / 分级预处理，AO 随机采样存在波动。0.2.13 已验证同核同噪声的 AO、深度预处理、单通道存储 GPU 读回一致，见前一版报告。

## 同画质性能对照

Windows / Edge / ANGLE D3D11，1920×1080 CSS 视口，设备缩放 1.5×，实际渲染 2880×1620。1000 专辑、两类流派、三个重复封面 URL，136 个驻留图集槽位；同相机、完整模型、相同阴影 / AO / 景深参数。每种状态预热后采 64 帧 GPU 硬件计时，重复两轮，表中取两轮中位数的平均。手动统一逐帧推进，排除旧版无上限与新版默认 60 FPS 的差别。

| 状态 | 下载原版 0.2.9 | 新版原画质 | 每帧 GPU 时间减少 |
| --- | ---: | ---: | ---: |
| 日间静止 | 6.29 ms | 4.28 ms | 32% |
| 夜间静止 | 6.35 ms | 4.13 ms | 35% |
| 日间持续动效 | 6.22 ms | 6.20 ms | 约 0% |
| 夜间持续动效 | 6.51 ms | 6.20 ms | 约 5% |

静止缓存有明确收益；持续动效下收益有限。CPU 提交中位数约 1.0–1.4 ms，未显示稳定的大幅下降。这些结果不能直接换算成任务管理器 3D 百分比，也不能据此宣称用户此前的 25% 占用问题已完全解决。

上述工作集中，图集原版固定 156 MiB，新版按需 48 MiB，减少 108 MiB（69%）。随不同封面 / 文字卡数量增加可扩至 156 MiB，不是所有曲库都固定省 108 MiB。AO 两个中间结果由 RGBA16F 改为 R16F，颜色缓冲理论从约 71.2 MiB 降至 17.8 MiB，同时去掉不需要的深度附件；保留法线与深度输入。该分项计算不等于整个进程的实测内存下降。关闭 SMAA 时两个中间目标缩到 1×1，避免保留全尺寸逻辑缓冲。

## 低需求性能版

在同一安装包中进入“设置 → 画面与声音 → 画质 → 低需求性能版”。默认仍为原画质优化版，主动选择后立即生效并保存。帧率独立保存，切换预设不覆盖既有帧率。

| 设置 | 原画质优化版 | 低需求性能版 |
| --- | --- | --- |
| 渲染比例 / 像素密度上限 | 100% / 1.5× | 80% / 1× |
| 模型 | 完整 | 自动分级，近看恢复完整 |
| 抗锯齿 | 原版关闭；可手动 SMAA | FXAA，细线和纹理会柔化 |
| 阴影 | 2048 | 1024 |
| AO / 景深 | 32 采样 / 100% | 关闭 |
| 透明材质分辨率 / 过滤 | 100% / 16× | 50% / 4× |
| 面板、曲库、歌词、播放功能 | 完整 | 完整 |

同一测试中，低需求档约 2.95–3.28 ms/帧，相比下载原版减少约 49–53%；这是以清晰度、远处倒角、接缝阴影、景深与折射细节为代价。可另选 30 FPS 继续降低负载，代价是动画流畅度下降，不将这部分算入同画质优化。

## 原生桌面窗口实测

0.2.14 的两个档位在同一 Electron 开发宿主、隔离资料目录、RTX 3090 / ANGLE D3D11 下依次测试。1920×1080 视口、1.5× 设备缩放、1000 张独立专辑 / 12 流派、连续上下切换，日间和夜间分别采样。Windows 计数器仅归属该窗口的 GPU 进程，六次采样取中位数；实际 FPS 来自真实渲染提交计数，不能用约 133 Hz 的外层 RAF 回调频率替代。

| 新版档位 | 实际渲染尺寸 | 实际 FPS（日 / 夜） | GPU 进程 3D（日 / 夜） | 专用显存（日 / 夜） |
| --- | --- | --- | --- | --- |
| 原画质优化版 · 60 FPS | 2880×1620 | 58.8 / 58.3 | 24% / 22% | 1157 / 1202 MiB |
| 低需求性能版 · 60 FPS | 1536×864 | 57.8 / 58.6 | 4% / 5% | 622 / 621 MiB |
| 低需求性能版 · 30 FPS | 1536×864 | 29.6 / 29.6 | 3% / 3% | 617 / 621 MiB |

全宿主进程私有内存之和分别约 2196–2410 MiB、1798–1800 MiB、1816–1823 MiB。顺序测试会受到分配器、缓存和宿主状态影响，因此作为短时样本报告，不保证每台机器同幅度下降。本组独立专辑的图集确实扩到 156 MiB，验证前述按需内存节省有边界；关闭高分辨率后处理与更小内部尺寸仍明显减少显存。

原画质高占用仍在，不能以低需求档的数据声称已经无损解决。原生桌面对比的是新版内部的档位差别；下载原包与新版的等画质对比见上一节 GPU 计时。

## 复核方式

- `npm test`：20 项通过。
- 画质参数 / 48 组设备限制检查、设置页滚动 / 草稿 / 焦点 / 动画检查通过；更新旧测试夹具以包含早已存在的歌词面板和已恢复的 1.5× 默认值。
- 实际帧率上限 24 / 30 / 60 / 120 分别提交 24 / 30 / 60 / 120 FPS；阴影缓存与强制刷新读回差异为 0，绘制由 23 次降至 21 次。独立创建 360° 查看器，WebGL 上下文确认 `antialias: true`、无 GL 错误。
- `scripts/check-original-comparison.mjs`：实际原包 / 新构建的设置控件、样式、截图、相机与 GPU 计时；`RHINE_PANELS_ONLY=1` 追加歌词与总览界面操作。
- 原始证据存于本地 `.cache/comparison-0.2.14/`，包含原版 / 新版 JSON、各面板截图及新增控件清单。测试使用合成曲库，不写入用户资料。
- 原生宿主证据存于宿主本地 `.cache/rhine-performance-comparison-0.2.14-1792472950782/`，含六组 CPU / GPU / 内存结果和截图。AA 三档、完整 / 自动模型及两个预设切换均经过实际菜单操作，未出现页面错误或上下文丢失。

GPU 硬件计时与原生宿主运行检查分别记录；实际占用受分辨率、帧率、窗口状态、曲库和其他 GPU 进程影响。
