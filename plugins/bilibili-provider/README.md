# Bilibili Favorites Provider

Twilight Echo provider plugin:

- plugin id: `com.twilightecho.provider.bilibili`
- provider id: `bili`
- type: `provider + ui`

## 功能

- Web QR 登录
- **账号简介** — 从已登录账号资料读取真实个人简介，与登录态一同缓存；资料接口异常时仍保留登录状态
- **流媒体页 Bilibili 入口** — 在流媒体页侧边栏拥有「Bilibili」小项，点击进入独立的搜索与收藏夹视图
- **搜索** — 在 Bilibili 页搜索 B 站视频，结果按视频首 P 映射为可播放曲目
- **收藏夹浏览** — 列出用户创建/收藏的视频收藏夹
- **红心取消收藏（0.1.17）** — 收藏夹内歌曲默认显示为已收藏；配合新版主程序，点击列表或播放器红心会实际取消 B 站收藏。同一视频的全部分 P 同步更新，取消会移出账号所有包含该视频的收藏夹；再次收藏加入默认收藏夹。失败时保留原状态并显示错误，成功后清除曲目分页缓存。
- **多 P 折叠与分页（0.1.18）** — 收藏夹内多 P 视频默认折叠，点击视频下方「展开分P」显示分 P 标题、独立时长与播放入口，每页 20P，支持上一页、下一页和页码跳转。定位正在播放的歌曲会展开对应视频并跳到所在页；收藏夹内搜索自动展开匹配的分 P。新版主程序支持该界面，旧版仍以平铺曲目呈现。
- **准确识别多 P** — `first_cid` 不再被当作单 P 标志；多 P 或未知分 P 数的视频会读取详情。每个分 P 保留独立 CID 和时长，音频获取失败时不会错误回退到首 P。
- **置顶收藏夹** — 可固定一个或多个收藏夹置顶显示
- **Cookie 静默刷新** — 利用登录返回的 `refresh_token`，在 SESSDATA 即将轮换时通过
  `passport.bilibili.com/x/passport-login/web/cookie/refresh` 静默续期，无需重新扫码
- **设备 Cookie 补全** — 登录后自动附加 `buvid3`/`buvid4`（`finger/spi`），与 B 站 Web 端请求姿态一致，降低风控慢响应概率
- **播放热路径缓存** — 登录态（60s）与 WBI 签名密钥（10min）缓存复用，切歌时不再重复请求 `nav`，整条 `getPlaybackUrl` 链路远低于宿主 30s RPC 超时
- **收藏夹缓存 TTL** — 收藏夹曲目缓存 10 分钟后自动失效，B 站 App 新收藏的内容能被及时看到
- **收藏夹按需分页（0.1.16）** — 配合支持 `fetchPlaylistTracksPage` 的主程序，打开收藏夹只请求一页（最多 20 个视频），滚动到底部或点击「加载更多」才请求下一页；不预取其他页，没有旧完整接口的 50 页上限。视频和分 P 保持原顺序，播放、搜索和排序使用已加载歌曲。后续页失败保留已有歌曲，只在手动重试时继续当前页。
- **减少音乐库请求** — 收藏夹列表直接使用列表接口提供的封面，不再逐个查询收藏夹首条视频。补充视频详情最多并发 2 个请求；旧主程序的完整列表接口改为逐页串行请求。
- **分页缓存与网络恢复** — 每页缓存 10 分钟，重复请求合并、账号会话隔离；刷新第一页会失效该收藏夹的其他页缓存，旧请求不会回写。临时断线、HTTP 5xx 或响应正文超时最多重试一次，接口明确拒绝时停止并保留错误码；登录检查的网络故障不会被当成登录失效。
- **网络恢复** — 冷启动登录检查和二维码生成可重试一次临时连接错误；限流响应遵守 `Retry-After`，不会立即重复请求。二维码轮询和 Cookie 刷新的响应正文也受超时保护，播放地址的整个回退过程限时 27 秒，避免连续超时触发宿主保护。
- 仅音频播放 — 通过本地 `127.0.0.1` 代理转发 DASH 音频流，不下载或展示视频画面
- **DASH 高音质优先** — 播放地址优先走 DASH 音频轨（会员 Hi-Res FLAC 参与择优），渐进式流（`platform=html5`）仅作兜底
- **失效曲目自愈** — 播放地址返回曲目不存在时自动用 `view` 接口刷新 cid 重试一次；确认失效的曲目快速失败并给出明确提示，不影响后续曲目播放
- **代理可靠性** — 上游 CDN 请求带响应头超时（15s），挂起的 P2P 边缘节点自动切换 `backupUrl`；客户端断开（seek/切歌）会取消上游拉流；stream 令牌有效期 6 小时，覆盖暂停后 seek
- 封面与头像 — 经同一本地代理注入 B 站 CDN 所需的 Referer / User-Agent 头
- 私有 Cookie 存储 — 仅写入插件私有 settings 文件

## 依赖与边界

- 依赖 Twilight Echo 的 provider API 与 UI 集成点。
- 真正按需分页需要同时更新支持 `fetchPlaylistTracksPage` 的主程序；只升级插件时，旧主程序仍调用完整列表接口，无法增量显示歌曲。
- 不携带宿主内部模块，不在运行时加载远程代码。
- 遵循 Twilight Echo 插件规范（见主仓库 `docs/twilight-echo-plugin-spec.md`）。

## 已知限制

- 搜索结果中每个视频需额外请求一次 `view` 接口解析 `cid`，已做并发（6）与 `limit` 截断控制。
- Cookie 静默刷新仅对「即将轮换但尚未失效」的 SESSDATA 生效；若 Cookie 已完全过期，仍需重新扫码。
- 分页接口每次只加载指定页，游标以原始视频位置计算，独立于失效视频过滤和分 P 展开后的歌曲数量；无法准确获知全部可播放歌曲数时返回 `total: null`。可显式 `force=true` 立即刷新。
- 旧主程序的完整列表接口保留最多 50 页的兼容边界；超过 1000 个视频的收藏夹应使用支持分页的新主程序。
- 收藏夹一次完整加载限时 105 秒，避免触发宿主 120 秒 RPC 超时；缓存兜底不会延长缓存有效期，缓存过期后的访问或再次强制刷新仍会尝试加载。B 站明确拒绝登录或访问权限时不使用旧缓存兜底。
